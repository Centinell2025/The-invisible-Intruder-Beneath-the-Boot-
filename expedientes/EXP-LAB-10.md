# EXPEDIENTE LAB-10: Boot Driver

**Clasificación:** simulación educativa DFIR. **Estado:** especificación; todavía no ejecutable ni validada como Insane. **Entidad ficticia:** Northbridge Systems.

## Dónde se aplica
Integridad de controladores de arranque.

## Función del laboratorio
Priorizar controladores para verificación.

## Aplicación práctica
Contrastar controladores con firmas y línea base.

## Evidencias que deben construirse
Inventario de drivers, catálogos, hashes. Se requiere procedencia, marcas UTC, identificadores únicos y manifiesto SHA-256.

## Procedimiento del investigador
1. Validar integridad y origen de las evidencias.
2. Correlacionar dos o más fuentes y normalizar horarios.
3. Evaluar hipótesis legítimas y sospechosas.
4. Citar identificadores de registros para cada conclusión.
5. Documentar incertidumbres y siguiente adquisición.

## Resultado verificable esperado
Lista de validación. La clave del instructor debe demostrar una respuesta única y reproducible.

## Prueba de calidad pendiente
Generar artefactos independientes, comprobar consistencia, resolver el caso a ciegas, revisar respuesta y cadena de custodia.

## Reserva de propiedad intelectual
No contiene el libro privado CoreShield, algoritmos, comandos, diseños internos, datos reales ni direcciones IP operativas.
